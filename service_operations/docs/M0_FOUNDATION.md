# M0｜设备售后服务运营样本与口径

> 状态：M0 样本基线 v1；2026-09-28。所有设备台账、站点、工单、SLA 均为合成演示数据。厂商手册是真实公开材料，不能将样本工单视为 LulzBot 的服务记录。

## 业务范围与任务

场景为一家虚构的增材制造设备服务团队，管理 TAZ Pro 与 TAZ Workhorse 两种型号、三个虚构站点。服务经理查询修复时间、SLA 与重复故障，现场工程师依型号和查询日期查手册。首版问题和证据如下：

| 类型 | 示例问题 | 必须给出的证据 |
| --- | --- | --- |
| 文档 | “TAZ Pro 出现 `PROBE FAIL CLEAN NOZZLE`，手册从哪里开始排查？” | TAZ Pro 手册第 5.1 节、页码、来源 URL、文档版本与适用型号；不能把 Workhorse 内容混入 |
| 指标 | “2026 年第二季度 TAZ Pro 的 MTTR 与前一季度相比如何？” | 两个按上海时间定义的半开季度、已解决工单 ID 集合、样本数、小时均值、差值及数据快照 |
| 混合 | “近三个月 TAZ Pro 的 `NOZZLE_WIPE` 重复故障率有无上升？现在该看哪份排障材料？” | 两段等长区间的分子／分母、重复事件的前序工单、当前生效文档的来源与版本；`NOZZLE_WIPE` 是内部演示分类，映射到手册原文的 `PROBE FAIL CLEAN NOZZLE` |
| 拒答 | “TAZ Workhorse 的 E17 官方处理流程是什么？” | 指出样本没有核实 E17 与该型号的对应关系，不编造步骤 |

故障分类 `NOZZLE_WIPE`、`HOTEND_TEMP`、`FILAMENT_FEED`、`BED_ADHESION`、`MOTION_AXIS` 是本项目自定义的**合成工单分类**，并非厂商错误码。检索时须把分类映射为型号对应的手册术语，再核对原文。早期设想中的 A/E17 只是需求占位例子，后续验收使用本表中的实际型号和术语。

## 来源与版本规则

来源清单见 [`manual_sources.json`](manual_sources.json)。两份选定的官方 PDF 均在首页标示 CC BY-SA 4.0；作者为 Aleph Objects, Inc.，本项目展示时保留作者、原链接、许可与修改说明。清单中的 `source_release` 是官方**目录路径**的标识，不声称是手册修订号；`demo-registry-v1` 只是本项目注册表版本，`effective_from` 是虚构服务团队采用该 PDF 的演示日期，不是厂商发布日期。M0 阶段只选来源，并未下载或索引。M2 已下载、核验 SHA-256 与 PDF 页数，并记录在清单；索引结果见 [M2 说明](M2_IMPLEMENTATION.md)。

为了测试“同一逻辑文档的新旧版”，另有两份项目自编的[服务记录流程便签](notes/)。它们只是虚构组织的行政流程，不是 LulzBot 官方技术指引。v2 的生效时间为 2026-07-01 00:00（上海时间）；查询旧日期选 v1，查询当前日期选 v2。未来 M2 将其转换成可摄取的 PDF 并验证版本筛选。不可用它们代替官方设备操作说明。

## 输入契约 v1

样本文件由 `python -m service_operations.generate_m0` 生成到 `service_operations/examples/m0/`。使用 UTF-8、CSV 首行字段名、UTC ISO 8601 时间戳（尾部 `Z`）。空值用空字符串，ID 为区分大小写的文本。导入时全批校验，严重错误拒收整个快照。

| 文件 | 必填字段 | 约束 |
| --- | --- | --- |
| `assets.csv` | `asset_id,model,site` | `asset_id` 唯一；`model` 为 `TAZ_PRO`／`TAZ_WORKHORSE`；`site` 为 `EAST`／`SOUTH`／`WEST` |
| `work_orders.csv` | `work_order_id,asset_id,fault_code,priority,opened_at,resolved_at,status` | ID 唯一、设备外键存在；优先级 `P1/P2/P3`；状态 `resolved/open`；已解决必须有 `resolved_at >= opened_at`，未解决须留空；工单只能属于一个设备 |
| `sla_policies.csv` | `policy_id,priority,effective_from,effective_to,resolution_hours` | 同优先级的生效区间不重叠，左闭右开；空 `effective_to` 表示长期有效；小时为正整数 |
| `invalid/invalid_work_orders.csv` | 与 `work_orders.csv` 相同 | **故意非法的拒收样本**，绝不可与有效快照直接拼接；`invalid/invalid_cases.json` 列出期望规则 ID |

`due_at` 不从 CSV 导入：按 `opened_at` 匹配唯一的有效 SLA 策略，增加自然小时计算。没有匹配或匹配多条均为严重错误。记录时间不得晚于样本 `as_of`；导入真实数据时应额外校验未来时间与合理范围。快照元数据、原始文件哈希与质量问题由 M1 导入器保存。

## 指标字典 v1

所有时间筛选先以 `Asia/Shanghai` 的 `[start,end)` 表达，再转换为 UTC。`as_of` 用于排除尚未到期的 SLA；样本默认 `2026-09-28T00:00:00+08:00`。过滤 `model/site/priority` 作用于工单所属设备和工单优先级。结果必须携带筛选条件、快照、口径版本和构成记录 ID。

| ID | 计算 | 时间归属与边界 |
| --- | --- | --- |
| `mttr_hours` | 已解决工单的 `resolved_at-opened_at` 小时数的算术平均；分母是已解决工单数 | `resolved_at` 在查询区间；跨期打开、期内解决计入 |
| `sla_attainment` | `resolved_at <= due_at` 的到期工单数／全部已到期工单数 | `due_at` 在区间且 `due_at <= as_of`；到期仍未解决或逾期解决均失败；恰好到期解决为成功 |
| `repeat_fault_rate_30d` | 有前序已解决工单的本期新工单数／本期新工单数；前序须同一 `asset_id+fault_code`，其 `resolved_at` 在 `[opened_at-720h,opened_at)` | 新工单 `opened_at` 在区间；仅查当前区间会漏掉前序，须向前读 30 天历史；同一新工单最多计一次 |

三项指标分母为零时返回 `null` 与 `NO_ELIGIBLE_RECORDS`，不返回 0。环比使用相邻、等长区间，同时展示分子／分母与绝对变化；百分比变化仅在前期非零时给出。SLA 是**合成合同口径**，按 24×7 自然小时，不代表厂商承诺。

## 合成规则与复现

参数机器可读版本见 [`config/m0.json`](../config/m0.json)，生成脚本就是执行定义。固定随机种子 20260928，按本地日期从 2025-10-01 至 2026-09-01（不含）生成；每天固定 2 张工单，共 670 张。18 台虚构设备均匀分配至两个型号、三个站点。普通工单先随机选设备，再按型号权重选故障类别；所有工单按权重选优先级。约 18% 的工单尝试从前 30 天内已解决的记录中复制“同设备、同故障”组合作为重复事件；候选不存在时改为普通事件。普通随机分配也可能自然形成重复，最终重复率必须由指标逻辑计算，不能把 18% 当作实际重复率。`NOZZLE_WIPE` 只在 TAZ Pro 上抽取，避免把 Pro 专属手册提示错误套用于 Workhorse。

2026-04-01 起，TAZ Pro 的 `NOZZLE_WIPE` 抽样权重被人为调高，以制造可分析的趋势；这是教学情景设定，不是厂商故障统计。修复时长按优先级的对数正态分布抽取，南站在 2026-07-01 后乘以 1.35 作为模拟拥堵；时长截断在 0.5～240 小时。仅最后 90 天的工单有 8% 的概率标记 `open`（本次固定种子实际产生 10 张）；这部分无解决时间，但只对到期且过了 `as_of` 的 SLA 造成失败。P2 策略于 2026-04-01 由 72 小时调整至 48 小时，其余 P1=24、P3=168 小时；这是虚构合同变更，用于检查策略生效边界。

无效样本单独生成，覆盖重复 ID、未知设备、非法优先级、已解决却缺解决时间、解决时间早于创建时间、非法时间戳；它用于 M1 的整批拒收验收，不影响有效快照。`sample_manifest.json` 记录每个输出文件的 SHA-256、行数、生成器版本、种子与时间范围。`reference_cases.json` 给出独立 Python 参考计算的分子、分母、结果和工单 ID，可作为 M1 SQL 实现的核对基线。相同 Python 版本与脚本运行两次，应得到相同文件字节和哈希。

## M0 交付边界与下一步

M0 固定了任务、指标、schema、手册来源与可复现样本，并未完成导入、SQL 指标或 PDF 检索。M1 从本样本契约实现快照导入、质量报告与三项指标；M2 下载并核验官方 PDF，增加手册注册和版本索引。若官方链接或许可文本变化，先更新来源记录，再重新生成检索验收集。
